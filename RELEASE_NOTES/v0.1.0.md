Erstes Release des **Checkmk-Cockpit-Plugins** für die Client-Aktualisierung.
Ab jetzt liegt die „Client aktualisieren…"-Funktion nicht mehr im Cockpit-Kern
(wo sie jeder Nutzer bekam), sondern als optionales Plugin — nur wer die DLL
in seinen `plugins/`-Ordner legt, sieht den Menüpunkt.

Braucht **Cockpit v1.7.0+** (ab da ist das Plugin-System im Cockpit-Kern).

## Was drin ist

- **`IContextMenuContribution`** für den Menüpunkt „Client aktualisieren…" in
  Status-Grid, Baumansicht und Hosts-Liste. Order = 1000 (landet unter den
  Cockpit-eigenen Einträgen mit Separator).
- **`IAgentUpdater`-Service** (aus `Checkmk.PluginContracts.Services`), im
  DI-Container registriert — andere Plugins (z. B. das kommende
  vSphere-Baseimage-Plugin) können ihn zum Batch-Update nutzen.
- **Skript-Vorlage + Agent-Share** werden aus dem Cockpit-Kern übernommen:
  Deinstall → Install → Register mit `--trust-cert`, `msiexec`-Calls mit
  `-PassThru`-ExitCode-Check.
- **Dialoge**: `CredentialDialog` (Admin-Anmeldung) und `AgentUpdateWindow`
  (Fortschritts-Log). Beide im Kroste-Look via dupliziertem `ChromeWindow` +
  `TitleBar` (Application-Resources kommen zur Laufzeit vom Cockpit).

## Konfiguration

Plugin-Settings liegen unter
`%APPDATA%\Kroste\Checkmk\plugins\kroste.checkmk.agent-updater\settings.json`
mit Defaults für Agent-Share (Samba01) und Skript-Vorlage. Bei Bedarf per
Editor anpassen; eine In-App-UI ist noch nicht dabei.

## Installation

ZIP dieses Releases herunterladen, entpacken, `CheckmkPlugin.AgentUpdater.dll`
in `plugins/` neben `Checkmk.App.exe` legen, Cockpit starten. Details siehe
[README](https://github.com/Kroste/Checkmk-Plugin-AgentUpdater/blob/v0.1.0/README.md).

## Voraussetzungen

- Windows (WinRM/PowerShell-Remoting).
- Checkmk Cockpit **≥ v1.7.0**.
- WinRM am Zielhost aktiv.
- Admin-Rechte auf dem Zielhost.
